1 · Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site that captures leads, and an /admin CRM. /admin starts open and unprotected, and gets locked down with email-and-password Supabase Auth later in the build.

2 · How the pieces fit

Next.js (App Router)Renders the public site and /admin. Server code handles form submissions and all database reads and writes — nothing touches the database from the browser.
VercelHosts and deploys the app. Environment variables hold every secret. A git push deploys.
Supabase (Postgres)The database. Accessed server-side only, using the service key. Secrets never reach the browser.
ResendSends the confirmation email when a lead comes in. Wired in Build 2, once the sending domain is verified.

Environment variables

NEXT_PUBLIC_SUPABASE_URL — the Supabase project URL.

NEXT_PUBLIC_SUPABASE_ANON_KEY — the public anon key for any safe client-side reads.

SUPABASE_SERVICE_ROLE_KEY — the server-only key for all privileged reads and writes. Never exposed to the browser.

RESEND_API_KEY — authorises sending the confirmation email.

NEXT_PUBLIC_SITE_URL — the live domain, used for email links and redirects.

3 · The lead flow

  1. A visitor submits the contact form on the public marketing site.
  2. Server code upserts a People row by email — an existing person is matched, never duplicated.
  3. It creates a linked Contacts row in status new_lead.
  4. (Build 2) Resend sends a confirmation email from the verified domain.
  5. The operator sees the lead in /admin, newest first, and works it through the pipeline.
  6. Each status change writes one activity_log row, so the full history is kept.

5 · Relationships

  • One Person has many Contacts (inquiries).
  • One Contacts row has many activity_log rows.
  • One Person has many Orders.
